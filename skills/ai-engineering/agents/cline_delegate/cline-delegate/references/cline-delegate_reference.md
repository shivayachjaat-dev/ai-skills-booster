# Cline CLI Delegation & Supervision Technical Reference

## 1. Plan Mode vs. Act Mode Execution Semantics

The Cline CLI implements two discrete operational states:

| Dimension | Plan Mode (`--plan`) | Act Mode (`--act`) |
| :--- | :--- | :--- |
| **Permissions** | Read-only file inspection, architecture mapping | Full file create, edit, delete, and terminal tool calls |
| **Primary Output** | Markdown architecture RFC, dependency audit | Working tree git diff, code modifications |
| **Risk Profile** | Zero mutation risk; ideal for ambiguous requests | High mutation risk; requires strict scope whitelist |
| **Execution Gate** | Review and approval by orchestrator | Diff inspection + automated test harness execution |

---

## 2. Multi-Provider Flag Sanitization & Routing

When invoking `cline` programmatically from an orchestrator script, arguments passed to `--model` or `--provider` must be strictly sanitized against command injection:
- Acceptable characters: `[a-zA-Z0-9_\-\.:/]`
- Any metacharacters (`;`, `&`, `|`, `` ` ``, `$`, `\n`) are rejected at the parameter validation gate before shell invocation.

---

## 3. Working Tree Quality & Safety Gates

Before accepting modifications generated by `cline --act`:
1. **Scope Whitelist Verification**: Ensure no untracked files or modifications exist outside the target list.
2. **Regression Check**: Run the project's test suite via the orchestrator to confirm no existing functionality was broken.
3. **Rollback Mechanism**: If tests fail, execute `git checkout -- .` and report diagnostics back to the user or parent workflow.

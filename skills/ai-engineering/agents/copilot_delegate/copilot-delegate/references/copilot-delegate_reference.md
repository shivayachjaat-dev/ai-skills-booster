# GitHub Copilot CLI Delegation & Supervision Technical Reference

## 1. Copilot CLI Reasoning Effort Economics

The GitHub Copilot CLI features a granular reasoning effort control (`--effort`):

| Effort Level | Optimal Use Cases | Latency Profile | Token Expenditure |
| :--- | :--- | :--- | :--- |
| `low` | Typo fixes, docstring generation, boilerplate structs | $< 2.0\text{ s}$ | Minimal |
| `medium` | Standard CRUD unit tests, localized function bugfixes | $2\text{--}5\text{ s}$ | Moderate |
| `high` | Multi-module refactors, schema migrations, concurrency | $5\text{--}15\text{ s}$ | Significant |
| `max` | Formal algorithm synthesis, security auditing, complex proofs| $15\text{--}45\text{ s}$ | Deep Reasoning |

Calibrating effort to task complexity prevents token budget waste on routine coding passes.

---

## 2. Mode Separation: Plan vs. Mutating

- **Plan Mode (`--mode plan`)**: Restricts Copilot to read-only tools. The agent analyzes repository context, maps dependencies, and outputs an architectural implementation plan without altering any files.
- **Default Mutating Mode**: Permits file edits and command execution. The orchestrator must constrain mutating runs to an authorized file scope whitelist.

---

## 3. Pre-Landing Verification Gate

Before the orchestrator accepts changes generated by Copilot:
1. Verify working tree diff (`git diff --name-only`) strictly matches the authorized whitelist.
2. Execute the acceptance test command in an isolated subshell.
3. Reject unexpected changes to dependency lockfiles (`package-lock.json`, `poetry.lock`).
